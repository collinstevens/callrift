# Partial-clone blob hydration review

Status: locally validated; actual cross-platform CI remains pending.

Reading several missing blobs through git cat-file --batch previously caused one lazy fetch per blob. Local filtered-clone regressions reproduced three fetches for three source inputs, four for a complete snapshot, and six when an unavailable promisor preceded the working remote. The independently specified source text and selected-input boundaries were already correct.

The reader first reads requested full object IDs with lazy fetching disabled in that child process. Available blobs return immediately; missing positions are collected, hydrated together, and merged back into caller order. Warm inputs need no extra Git probe and do not query remotes. Arbitrary object expressions retain the original reader. Promisor discovery follows Git configuration order, including boolean promisor values, partial-clone filters, and the extension-designated remote last. Missing IDs are probed again after acquiring the hydration gate and after each fetch. Failed batches can therefore fall through to another remote without refetching completed inputs. Fetches use LF input, preserve FETCH_HEAD and refs, and respect an explicit GIT_NO_LAZY_FETCH restriction. Unsupported probe commands retain the original reader. The asynchronous gate prevents overlapping before/after hydration inside one GitRepository instance; it does not coordinate unrelated processes.

Ten isolated checks pass: selected source inputs, preserved binary bytes, non-default remote names, fallback remotes, concurrent revision reads, explicit fetch disabling, missing ordinary objects, cancellation before a read, cancellation during a blocked TCP fetch, mixed availability with repeated blobs and caller order, and arbitrary object expressions. Several checks combine related conditions. The first three batching cases failed before the change; their expected fetch bounds now pass. Repeated warm reads add no fetches. The final implementation passes all 55 existing ScenarioTests/QueryTests-filter checks (5m22s), all 51 real-world checks (14m02s), all 22 workspace checks (4m46s), package smoke, formatting, and workflow validation. Existing snapshots are unchanged.

Git's [2.45 release notes](https://raw.githubusercontent.com/git/git/v2.45.0/Documentation/RelNotes/2.45.0.txt) introduce the probe option. Its [command documentation](https://raw.githubusercontent.com/git/git/v2.45.0/Documentation/git.txt) equates the process environment setting with that option. The [pinned promisor implementation](https://raw.githubusercontent.com/git/git/v2.45.0/promisor-remote.c) supplies the remote-order and batch-fetch behavior used for this review. The change introduces no new minimum Git version.

A fresh external shallow/filtered OrchardCore client also passed the full source-mode breadcrumb comparison at cd7d8430905d2f2ab3ba3aef49577d73647ccfbf to 4910d1722d33f1b06d9ddb1cf8f6de2aa871dc8a. The after tree contains 5,641 C# files. Both snapshot reads caused two fetches total, and every JSON field matches the reviewed trial: 379 roots and 16,222 diagnostics. The unrelated logo.png blob remains missing. This is large-repository input/output verification under concurrent validation load, not a timing result or whole-pair semantic acceptance.

Controlled [BenchmarkDotNet results](../../benchmarks/README.md) preserve seven full exports, implementation hashes, immutable inputs, environment/cache conditions, and the patch for the discarded first version. An initial extra probe made warm reads 39.7% slower. Reading available blobs first removes that measured penalty: 205.18 ms versus a repeated 206.45 ms baseline, with overlapping confidence intervals. Fresh local clients reading twenty selected blobs improve from 3.63 s to 0.39 s for Serilog and 5.59 s to 0.50 s for Polly. Managed parent allocations increase; Git subprocess heaps and full analysis are outside this measurement.

The benchmark project moves from BenchmarkDotNet 0.15.8 to [0.16.0-preview.2](https://www.nuget.org/packages/BenchmarkDotNet/0.16.0-preview.2) because 0.15.8 fails .NET 11 runtime recognition. Both measured implementations use the same preview package and lock. All seventeen changed benchmark dependency license references were reviewed as MIT, including the two legacy license URLs; the metadata records the pinned ProtectedData source license. Runtime package dependencies are unchanged.
